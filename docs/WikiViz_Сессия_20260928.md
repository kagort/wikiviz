## 1. Почему сменился инструмент

В прошлой сессии Phase 6 (TableWidget, GalleryWidget, MapWidget, SectionNavigator) продвигалась медленно: PowerShell плохо передавал длинные блоки кода (обрывы, пропавшие строки — история с исчезнувшим `<a>` в `SectionNavigatorView.tsx`), плюс визуальная проверка данных требовала параллельно разбирать разметку Wikipedia, чинить extractor и вести диалог в чате — три задачи одновременно. Решение: описать оставшуюся работу как ТЗ (`docs/PHASE6_TZ.md`, подготовлен в прошлой сессии) и передать её Claude Code — агенту, который сам пишет код, запускает тесты и коммитит, а Claude в чате разбирает его отчёты и перепроверяет результат независимо.

### Этап 2 — исправления extractors

**2.1. Гипотеза про оглавление France не подтвердилась.** Лишние пункты (`Economy`, `Government`, `Culture` после `External links`) — не заголовки навигационных блоков, а настоящие подразделы `External links` со списками ссылок; в данных вложенность была верной, просто пропала при копировании текста страницы в чат. Кода агент не менял, только подтвердил разведкой на всех пяти статьях (en и ru).

**2.2. Сноски исправлены.** Общий модуль `backend/app/extractors/text_utils.py`: проверка «это сноска/служебный элемент» (те же принципы, что раньше применялись к скрытым sort-key spans в таблицах и к заголовкам разделов). Применена к ячейкам таблиц (включая строку-шапку), `caption` таблиц и подписям изображений. Заодно нашлась сноска в подписи картинки — монета Цезаря, `[191]`. Обычный верхний индекс (например, `км²`) не трогается.

**2.3. Код в ячейках больше не разбит пробелами.** Причина: подсветка синтаксиса делит одно выражение на много вложенных элементов, а прежняя логика ставила пробел между каждой парой. Теперь текст внутри одного фрагмента кода склеивается без пробела, между разными фрагментами пробел остаётся (тест на `True False` не сломан). Было `bytearray ( b 'Some ASCII' )`, стало `bytearray(b'Some ASCII')`.

**Проверки:** backend 147 → 157 (10 новых тестов, 8 изначально красные, 2 защитные).

**Известные ограничения, не исправлены:**

- Инфобокс Цезаря: `Pontifex maximus 44 BC` — год конца периода принят за отдельную дату, начало периода (`64 BC`) потеряно.
- Таблица-навигация («Political offices / Religious titles» у Цезаря) извлекается как настоящая таблица с данными — извлекатель различает только `infobox`/`navbox` по классу, а не более широкий класс «служебная, не про данные» таблиц.
- Закреплённые ревизии фикстур не защищают от изменений в общих шаблонах Wikipedia (навигация, вёрстка инфобокса) — раз в несколько месяцев возможны мелкие расхождения при повторной выгрузке.

**Процессные находки:**

- На свежей машине для frontend: сначала `npm run build`, потом `npx tsc --noEmit` (иначе типы Next.js ещё не сгенерированы).
- Облачные сессии Claude Code по умолчанию не имеют доступа к Wikipedia — нужно один раз настроить `Network access: Custom` с `*.wikipedia.org`/`*.wikimedia.org` в настройках среды.
- Каждая новая облачная сессия — чистый контейнер: зависимости (venv, npm) ставятся заново, ничего не переносится автоматически между сессиями агента, кроме того, что закоммичено в git.
- `WikipediaClient` с `trust_env=False` (намеренно, из-за проблемы с VPN-прокси на Windows) в облачной песочнице агента тоже не видел нужный сертификат — агент обошёл это временной обёрткой вне репозитория, не трогая клиентский код. Хороший пример: если правило добавлено ради одной среды (Windows/VPN), не нужно его ломать ради другой (облако) — среда-специфичные обходы должны оставаться среда-специфичными.
- Owner всегда самостоятельно перепроверяет числа тестов и результат сборки после работы агента, а не полагается только на текст отчёта — в этот раз расхождений не нашлось, но это действующее правило проверки, а не разовая случайность.
